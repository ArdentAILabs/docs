Ardent creates instant, isolated copies of your production Postgres database — in seconds, right from your terminal.

Test migrations, run schema changes, and let coding agents like Claude Code and Cursor actually verify their database work — all against real data, without touching production.

No more shared staging databases. No more hand-maintained fixtures. An instant database for every task.

mkdir -p .claude/skills/ardent-cli

  exit 1
fi

To guarantee it's used, add this to your project's `CLAUDE.md`, which Claude Code reads every session:

seeds, or queries against real data, use the ardent-cli skill and work on an
Ardent branch. Never use the main connection string unless the user

Without the skill, paste the full directions into your agent:

```
Set up Ardent for database branching. Act like a teammate at my keyboard:
run the commands yourself, stop only when you need me to do something
only I can do (browser sign-up, paste a credential, run source-database SQL).
Before each step, give me one short line on what's happening and why.

Run these in order:

1. Install the CLI: npm install -g ardent-cli

2. ardent login → opens a browser to authenticate. Tell me to finish
   sign-up or login and ping you when done.

3. Tell me to export my Postgres connection string in this shell:
   export ARDENT_DB_URL='postgres://...'
   Then run:
   ardent connector preflight postgresql "$ARDENT_DB_URL"
   If preflight prints a Grant script, stop and ask me to run it on the
   source database, then re-run preflight until it passes.

4. After preflight passes, run:
   ardent connector create postgresql "$ARDENT_DB_URL"
   Setup runs server-side and may take minutes or longer depending on
   database size. If it's interrupted, resume with:
   ardent connector retry-setup <name>

5. ardent branch create my-feature → an isolated copy of my database
   I can use however I want without touching prod.

6. ardent branch info → hand me the connection URL. I connect to it
   like any Postgres database.

If a command errors, fix it. Docs: https://docs.tryardent.com/quickstart
```

## How it works

Ardent replicates your database into a [read replica](/architecture), then creates isolated **branches** from that replica in seconds. Each branch is a full Postgres database with your real data — like branches in git.

```
Production DB → Replication → Read replica → Many branches (each in seconds)
```

The workflow mirrors git:

- **[`ardent branch create`](/cli/branches)** — spin up an isolated database copy
- **`ardent branch switch`** — move between branches
- **`ardent branch info`** — see the connection URL and status
- **`ardent branch delete`** — clean up when you're done

Branches suspend after 5 minutes of inactivity and wake instantly on reconnect. You pay storage only for the changes you make on a branch — so create as many as you need and throw them away freely.
