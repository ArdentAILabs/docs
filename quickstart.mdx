<Info>
  **You'll need:**
  - Node.js 18 or newer
  - Access to your Postgres database (Supabase, RDS, PlanetScale, or self-hosted)
</Info>

<Steps>
<Step title="Install the CLI" id="install-the-cli">

```bash
npm install -g ardent-cli
```

</Step>

<Step title="Log in" id="log-in">

```bash
ardent login
```

Your browser opens — sign in or create your account there, then come back to the terminal.

```text

Create one with: ardent project create <name>
```
On a fresh account, create a project first: `ardent project create my-app`. If you already have exactly one project and connector, Ardent selects them for you.
</Accordion>

<Step title="Get your connection string" id="get-your-connection-string">

This is the Postgres URL of the database you want to branch — your source database's **writable primary**, not a read replica or pooler endpoint.

Save it in your shell so the next two commands can reuse it:

```bash
export ARDENT_DB_URL='postgresql://user:password@host:5432/mydb'
```

Keep the single quotes — passwords often contain characters your shell would eat.

Where to find it, and the one thing that usually blocks the next step:

<Tabs>
<Tab title="Supabase">
In your Supabase dashboard, open **Connect** and copy the [**direct connection** string — not the pooler one](/connectors/supabase#use-the-direct-connection-not-the-pooler). The pooler can't do replication, and preflight will fail on it. Details: [Supabase setup](/connectors/supabase).
</Tab>
<Tab title="RDS / Aurora">
Logical replication is usually off by default. [Set `rds.logical_replication = 1` in your parameter group](/connectors/rds#enable-logical-replication) and reboot before running preflight. Details: [RDS setup](/connectors/rds).
</Tab>
<Tab title="PlanetScale">
[Enable logical replication in the dashboard](/connectors/planetscale#enable-logical-replication), then use your Postgres connection string from **Connect**. Details: [PlanetScale setup](/connectors/planetscale).
</Tab>
<Tab title="Self-hosted">
Make sure [`wal_level = logical` in your Postgres config](/connectors/self-hosted#enable-logical-replication) (needs a restart if you change it). Details: [Self-hosted setup](/connectors/self-hosted).
</Tab>
</Tabs>

</Step>

<Step title="Preflight your database" id="preflight-your-database">

```bash
ardent connector preflight postgresql "$ARDENT_DB_URL"
```

Preflight checks whether Ardent can branch this database. It creates nothing and stores no credentials — it just tells you what, if anything, to fix.

If a check fails:

- **Missing grants** — preflight prints the SQL. Run it on your database, then run preflight again.
- **`wal level` fails** — logical replication is off. See your provider tab above.
- **"Already connected"** — this database has a connector. Run `ardent connector list`.

</Step>

<Step title="Connect your database" id="connect-your-database">

When preflight passes:

```bash
ardent connector create postgresql "$ARDENT_DB_URL"
```

This copies your data into Ardent once. Small databases take minutes; large ones take longer. Setup runs on Ardent's servers — if your terminal disconnects or you interrupt the command, nothing is lost. Run `ardent connector retry-setup <name>` and it picks up where it left off.

<Note>The new connector becomes your active connector automatically.</Note>

</Step>

<Step title="Create a branch and use it" id="create-a-branch-and-use-it">

```bash
ardent branch create my-feature
```

That's an isolated copy of your database, created in seconds. Prove it — connect and query:

```bash
psql "$(ardent branch info --print-url)" -c 'select count(*) from <your-biggest-table>;'
```

Real data, real Postgres, and nothing you do here touches your source database.

</Step>
</Steps>
