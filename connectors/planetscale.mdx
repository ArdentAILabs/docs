Ardent works with PlanetScale Postgres. This page covers only what's specific to PlanetScale — the full walkthrough is the [Quickstart](/quickstart).

<AccordionGroup>
<Accordion defaultOpen={false} title="Set up the ardent-cli skill with npx">
Install the skill once:

```bash
npx skills add ArdentAILabs/docs --skill ardent-cli
```

Then a short ask is enough — the skill fetches this page and runs the checks:

```
Check if my PlanetScale Postgres database is ready to connect to Ardent.
My connection string: [paste here]
```
</Accordion>

<Accordion defaultOpen={false} title="Set up the ardent-cli skill manually: SKILL.md and CLAUDE.md">
Install into your project (or into `~/.claude/skills/` to use it everywhere) and Claude Code loads it automatically whenever a task involves Ardent:

```bash
mkdir -p .claude/skills/ardent-cli
tmp_skill="$(mktemp)"
if curl -fsS https://docs.tryardent.com/skills/ardent-cli-skill.txt -o "$tmp_skill"; then
  mv "$tmp_skill" .claude/skills/ardent-cli/SKILL.md
else
  rm -f "$tmp_skill"
  exit 1
fi
```

To guarantee it's used, add this to your project's `CLAUDE.md`, which Claude Code reads every session:

```
Before touching the database in this repo — Postgres in any form, including
Supabase, RDS, PlanetScale, and self-hosted — for migrations, schema changes,
seeds, or queries against real data, use the ardent-cli skill and work on an
Ardent branch. Never use the main connection string unless the user
explicitly asks to change the real database.
```

Then a short ask is enough — the skill fetches this page and runs the checks:

```
Check if my PlanetScale Postgres database is ready to connect to Ardent.
My connection string: [paste here]
```

Self-update behavior, pinning, and the full skill contents: [AI agents](/workflows/ai-agents#let-the-agent-drive-set-it-up-once).
</Accordion>
</AccordionGroup>

Without the skill, paste the full directions into your agent:

```
Check if my PlanetScale Postgres database is ready to connect to Ardent.
My connection string: [paste here]

Use Ardent preflight first:
ardent connector preflight postgresql '<connection-string>'

Verify:
1. The host is reachable and credentials work.
2. Logical replication is enabled in the PlanetScale dashboard.
3. The URL points to the writable primary: SELECT pg_is_in_recovery(); must return false.
4. The user has replication privileges.
5. Tables selected for replication have a primary key, valid unique NOT NULL index, or REPLICA IDENTITY FULL.

After preflight passes, run:
ardent connector create postgresql '<connection-string>'
```

Two things matter here:

<Steps>
<Step title="Enable logical replication" id="enable-logical-replication">

In your PlanetScale dashboard, go to **Settings > Integrations** and enable **Logical Replication**. This is what lets Ardent replicate your data for branching.

</Step>

<Step title="Copy the connection string" id="copy-the-connection-string">

Go to **Connect > Connect with: Postgres** and copy the connection string. It looks like:

```text
postgresql://user:[YOUR-PASSWORD]@aws.connect.psdb.cloud/mydb?sslmode=require
```

Wrap it in single quotes in your shell — the `?sslmode=…` part must not be interpreted by the shell.

</Step>
</Steps>

From here, continue with the [Quickstart](/quickstart): run preflight, fix anything it reports, then create the connector.
